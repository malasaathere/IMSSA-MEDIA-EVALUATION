HOW TO USE THIS FILE
1. Open Google Stitch at https://stitch.withgoogle.com/.
2. Start a new web application design.
3. Paste MASTER PROMPT first to establish the product and visual system.
4. Generate each major screen separately using the numbered SCREEN PROMPTS.
5. Keep the same visual theme and component system across every generation.
6. Generate both desktop and mobile variants for each primary screen.
7. Use Stitch chat to refine a generated screen with the relevant REVISION PROMPT.

Do not paste every screen prompt into a single generation if Stitch simplifies or omits details. Generate one role workspace or one complex screen at a time.

MASTER PROMPT — PRODUCT, DESIGN SYSTEM AND GLOBAL UX
======================================================================

Design a polished, responsive web application named “IMSSA Media Evaluation”. It is an internal media-production and campaign-management platform for a university media organization. The application replaces disconnected spreadsheets, chats and file handovers with a traceable workflow for marketing planning, task assignment, creative production, review, approval, communication and analytics.

PRIMARY USERS
- Marketing Coordinators plan campaigns, create tasks and assign designers.
- Designers and Video Editors complete creative tasks and upload versions.
- Media Directors review submitted work, annotate it, approve it or request revisions.
- Chief Coordinators monitor delivery, deadlines and team capacity.
- Administrators manage users, roles, access requests and system health.

GLOBAL EXPERIENCE GOALS
- On every screen, make it immediately clear what needs attention, who owns it, when it is due and what happens next.
- Use progressive disclosure: cards show essential information; details appear in drawers, dialogs or dedicated pages.
- Keep task, event, assignee, deadline and status context visible during every workflow.
- Provide explicit loading, empty, validation, error, saved, offline and permission-denied states.
- Never communicate status with color alone; pair color with a text label and icon.
- Make primary actions obvious and place them close to the content they affect.
- Preserve history and evidence for assignment, upload, revision, review and approval actions.

VISUAL DIRECTION
- Professional, modern internal SaaS dashboard; calm and trustworthy rather than playful.
- Use a deep navy structure color (#0B2545), action blue (#2E74B5), teal accent (#0E7490), success green (#047857), warning amber (#B7791F), danger red (#9B1C1C), pale blue-gray surfaces (#E8EEF5) and light neutral backgrounds (#F4F7FA).
- Use Inter, Aptos or a similar clean sans-serif typeface.
- Body text should feel equivalent to 16 px; supporting text must remain readable.
- Use a 4 px spacing system with common gaps of 8, 12, 16, 24 and 32 px.
- Cards should have subtle borders, restrained shadows and 10–12 px corner radius.
- Use clear hierarchy, generous whitespace and compact but readable data density.
- Minimum touch target 44×44 px; prefer 48×48 px on mobile.
- Visible keyboard focus indicators with at least a 2 px contrasting outline.
- Meet WCAG 2.2 AA contrast and accessibility expectations.

GLOBAL APPLICATION SHELL
- Desktop: collapsible left sidebar, top navigation bar, page title, contextual actions and main content.
- Mobile: compact top bar with labelled menu button; navigation opens as a drawer.
- Sidebar items should appear according to the active role: Marketing, Marketing Plan, My Work, Review Inbox, Analytics, Calendar, Administration and Profile.
- Top bar includes global search, notification bell with unread count, role switcher for multi-role users, user menu and sign out.
- Add a floating Team Chat launcher with unread badge; use a full-height panel on desktop and full-screen sheet on mobile.
- Add a non-blocking system-status banner for synchronization or service problems.

CANONICAL TASK STATUS SYSTEM
- Draft: neutral gray, document icon.
- Assigned / To Do: blue, assignment icon.
- In Progress: cyan, progress icon.
- Ready for Review / In Review: purple, eye icon.
- Revision Requested: amber, revision icon.
- Approved / Completed: green, check icon.
- Cancelled: gray or red outline, cancelled icon.

CURRENT PRODUCT DATA TO USE IN MOCKUPS
- Campaigns: HackX 11.0, HackX Jr 9.0 and Exposition 2026.
- Users: 20 active team members with Marketing Coordinator, Designer, Video Editor, Media Director and Chief Coordinator roles.
- Use realistic task and marketing-plan data, not lorem ipsum.
- Example tasks: “Exposition 2026 Logo Design”, “Podcast Ep 1 Thumbnail” and “HackX Social Media Launch Flyer”.
- Show dates in a clear format such as “17 Jul 2026” and use Asia/Colombo timezone.

RESPONSIVE REQUIREMENTS
- 320–639 px: single-column content, drawer navigation, card alternatives to wide tables and sticky bottom primary actions.
- 640–1023 px: flexible two-column layouts and collapsible side panels.
- 1024 px and above: persistent sidebar and multi-panel workspaces.
- Do not allow page-level horizontal scrolling at 320 px.
- Complex dialogs become full-screen on narrow mobile screens.
- Charts need readable text summaries or table alternatives on mobile.

Generate reusable components and consistent variants for default, hover, focus, pressed, disabled, loading, error and success states.

REVISION PROMPTS FOR STITCH CHAT
======================================================================

REVISION A — Improve UX hierarchy
Refine this screen so the user can identify the next required action in under ten seconds. Keep task title, event, owner, deadline and status visible. Reduce decorative elements, improve whitespace and make the primary action unmistakable without making secondary information disappear.

REVISION B — Mobile optimization
Create a 360×800 mobile variant. Remove page-level horizontal scrolling, convert wide tables into readable cards, use a labelled navigation drawer, keep touch targets at least 44×44 px and place the primary action in a sticky bottom action area. Ensure the on-screen keyboard does not cover the active field or submit action.

REVISION C — Accessibility
Improve this design to meet WCAG 2.2 AA. Increase weak contrast, add persistent field labels, show visible keyboard focus, avoid color-only status communication, ensure logical heading order and make icon-only controls understandable with labels/tooltips.

REVISION D — Complete states
Add realistic loading skeleton, empty, validation error, network error with Retry, saved-success, offline/degraded and permission-denied variants. Keep navigation and page identity stable across states.

REVISION E — Data density
Use realistic IMSSA data and increase information density without reducing readability. Show HackX 11.0, HackX Jr 9.0 and Exposition 2026, realistic team members, assignees, task statuses and July/August 2026 dates. Do not use lorem ipsum.

REVISION F — Consistency
Align this screen with the established IMSSA design system: deep navy structure, blue primary actions, teal accents, neutral surfaces, consistent 4 px spacing grid, 10–12 px card radius, status chips with text/icons and accessible typography.
